# What BOSS takes from Paradev

Paradev is designed to let an operator run and observe several agents in isolated workspaces. BOSS marks a documentation project complete after an independent review covers the brief and the executable check passes at the published Git commit. The most useful changes for BOSS shorten the path to that evidence and tell the operator accurately when help is needed.

This review uses the owner's checkout at `eadb98ca83a66236e88dc1c5ea96fd44d259ff97`. Its root license is MIT. The findings below come from source and test inspection. The verification runs exercise the independent Elixir implementations in BOSS. ## Three changes on the path from brief to delivery

### Give the agent the task the operator named

Paradev's launch request explicitly contains the workspace, selected agent, task and automatic execution choice. Its test verifies the rendered task text and shows that preparing the prompt can leave execution disabled. In its automation path, supplemental trigger context gives way before the operator's own instructions, and the prompt identifies truncated payloads. [Task launch](https://github.com/ParadevAI/Paradev/blob/eadb98ca83a66236e88dc1c5ea96fd44d259ff97/packages/shared/src/agent-launch-request.ts#L110) · [Launch test](https://github.com/ParadevAI/Paradev/blob/eadb98ca83a66236e88dc1c5ea96fd44d259ff97/packages/shared/src/agent-launch-request.test.ts#L91) · [Trigger context budget](https://github.com/ParadevAI/Paradev/blob/eadb98ca83a66236e88dc1c5ea96fd44d259ff97/packages/trpc/src/router/automation/triggerContext.ts#L28) · [Escaped payload tests](https://github.com/ParadevAI/Paradev/blob/eadb98ca83a66236e88dc1c5ea96fd44d259ff97/packages/trpc/src/router/automation/triggerContext.test.ts#L27)

A BOSS Task Prompt can refer to several cards. Previously, earlier cards could use the budget before the named card appeared. Prioritizing explicit references lets an operator say which task to update in one request. The budget applies to auxiliary board context. The pinned Markdown, executable checks and full review evidence still follow the managed delivery protocol. [BOSS Task Prompt](../lib/boss/projects/task_prompt.ex) · [Regression tests](../test/boss/task_prompt_test.exs)

### Show who needs attention and what actually finished

Paradev maps lifecycle events into a small set of statuses and gives simultaneous agents an explicit attention ordering. Its automation list also distinguishes a dispatched run from a failed or blocked dispatch. That split is valuable when an active peer would otherwise hide a task needing a decision. [Event mapping and urgency](https://github.com/ParadevAI/Paradev/blob/eadb98ca83a66236e88dc1c5ea96fd44d259ff97/packages/shared/src/agent-status.ts#L22) · [Attention regression](https://github.com/ParadevAI/Paradev/blob/eadb98ca83a66236e88dc1c5ea96fd44d259ff97/apps/mobile/screens/%28authenticated%29/%28home%29/home/utils/strongestAttention/strongestAttention.test.ts) · [Automation status labels](https://github.com/ParadevAI/Paradev/blob/eadb98ca83a66236e88dc1c5ea96fd44d259ff97/apps/desktop/src/renderer/routes/_authenticated/_dashboard/automations/utils/runStatus/runStatus.ts#L14)

In BOSS, `ready_to_merge` means an independent reviewer approved a candidate. The branch may still move and a postcheck can still fail. The Autopilot dashboard must reserve Done for a persisted delivery in `done` and point to the task requiring attention even while a peer runs. Every indicator comes from saved state; rendering the panel cannot dispatch or integrate a task. [Autopilot panel](../lib/boss_web/components/autopilot_panel.ex) · [Publication gates](../lib/boss/deliveries.ex)

### Spend Git work at the point where the answer can change

Paradev’s renderer submits a workspace request with a client-minted ID. The host checks cheap inputs immediately and reports the canonical ID or a later failure when workspace creation settles. BOSS already saves intent before effects. The transferable idea is to spend each expensive check at the boundary where its result matters. [Workspace creation](https://github.com/ParadevAI/Paradev/blob/eadb98ca83a66236e88dc1c5ea96fd44d259ff97/packages/host-service/src/trpc/router/workspaces/workspaces.ts#L1443) · [Enqueue and settlement tests](https://github.com/ParadevAI/Paradev/blob/eadb98ca83a66236e88dc1c5ea96fd44d259ff97/packages/host-service/test/integration/workspace-create-enqueued.integration.test.ts#L53)

In the host implementation, an adoption helper receives a worktree path that its caller already resolved and still checks whether the worktree is independent. This is the narrower pattern BOSS can use within one operation. [Worktree adoption](https://github.com/ParadevAI/Paradev/blob/eadb98ca83a66236e88dc1c5ea96fd44d259ff97/packages/host-service/src/trpc/router/workspace-creation/shared/adopt-existing-worktree.ts#L51) · [Worktree integration test](https://github.com/ParadevAI/Paradev/blob/eadb98ca83a66236e88dc1c5ea96fd44d259ff97/packages/host-service/test/integration/workspace-create-delete.integration.test.ts#L186)

BOSS must verify that the target exists, points to the expected base, and is free of user checkouts. Resolving the same workspace twice inside one preflight bought extra Git child processes without an additional delivery boundary. Reuse a result inside that one operation. A later dispatch, review handoff, or publication still needs its own current evidence. [Workspace resolution](../lib/boss/agents/workspace.ex) · [Integration preflight](../lib/boss/deliveries/integration.ex)

## Measurements in BOSS

On the same synthetic 256-card board, the former Task Prompt encoder produced 152,191 bytes of JSON and zero specification bytes for either of the two addressed cards. The new encoder produced 96,799 bytes, under the 98,304-byte limit. Each addressed card received a 6,003-byte UTF-8 excerpt including the ellipsis. The prompt retained 202 detailed cards and identified the other 54 by ID. A separate test addressed task 258 by number through the live Task Prompt entry point. Explicit numbers such as `#258` receive priority before the project query’s 256-row limit. Textual task identifiers receive priority within the selected rows. These byte counts describe board context; they do not estimate model tokens, latency or billing.

An instrumented native documentation-intake validation launched 18 Git children before the change and 11 after it. Seven launches were removed from that boundary (39%). The measured operation still refused a changed target and an occupied publication branch. This is a process count for this operation; provider latency and overall delivery duration are separate measurements.

Rendered dashboard tests cover approval beside a published task and a blocked task beside an active peer. A headless browser reached the attention link by keyboard at 390 and 1,280 pixels. This keyboard check used the rendered fixture.

All three native greenfield scenarios passed on the combined changes. Starting with one committed Markdown brief, a finite agent CLI produced an application that passed every behavior check on the published commit. An empty planner result still led to whole-brief verification. In the incomplete-app case, an ordinary task passed but two required behaviors failed independently, and the final delivery stayed blocked.

## What to measure next

Use a fresh repository containing one committed brief, a saved executable check and a detached checkout of the publication. Compare time to the first admitted stage, the number of Git processes per preflight, whether a referenced task reaches the prompt within its byte limit, and time to a **whole-brief** Done. Include a run where an ordinary task passes while the brief still fails. These measures separate local orchestration cost from the provider's response time. Cloud hosts, external trigger services and cross-device chat solve different operational problems and add no evidence to this experiment.
