How it works

A workflow with receipts.

Agents do the reversible work. The control plane owns the durable story.

  1. 01

    Connect a local repository

    Cuckoding validates Git, policy, installed runtimes, and optional plugins.

  2. 02

    Create a board and task

    Choose a versioned workflow and map roles to supported agent runtimes.

  3. 03

    Run inside a dedicated worktree

    The trusted-host runner supervises processes and confines Cuckoding commands to declared paths.

  4. 04

    Watch gates and recoveries

    Committed events drive the UI; sleep gaps and failures are reconciled from durable state.

  5. 05

    Approve the handoff

    After evidence review, a host-side service can push the branch and prepare a draft pull request.

Built from boring, durable things

The stack that survives the night shift.

One local application. One browser UI. No hosted control plane and no second frontend framework.

  • Elixir / OTPSupervision and durable orchestration
  • Phoenix LiveViewLoopback-only real-time interface
  • SQLite + WALEvents, projections, evidence, recovery
  • Tauri + RustTray shell, updates, diagnostics
  • Git worktreesPer-run branches and workspace isolation
  • macOS KeychainOpaque secret references, never agent payloads

Honest by design

Powerful agents. Real boundaries.

The MVP runs agent processes on your Mac. Worktrees, policy, permission grants, and human gates reduce risk—but the host runner is not a container or sandbox.

  • Apple Silicon macOS is the first supported target.
  • Codex and Claude Code are supported; Cursor Agent and OpenCode remain non-selectable until conformance passes.
  • Cuckoding never autonomously merges or deploys production changes.
