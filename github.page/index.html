01 / Give the work a direction

From an idea to
work you can review.

A project, a crew, and a sequence you can follow. Each step carries its context forward.

A role for every part of the work.

SpecificationsCodingReview

Use one runtime across roles or assign a specialist to each. Codex, Claude Code, and Cursor Agent are supported launch adapters. OpenCode and Custom Agent are setup-only.

  1. 01
    Available now

    Make room for the project.

    Choose a local folder and Git branch, then review the registration. Setup creates no board, task, or agent run.

    Project → Repository → Review
  2. 02
    Available now

    Bring your agents together.

    Connect saved agents and assign project roles. Named Codex and Cursor agents can share a provider sign-in while using different models.

    Project settings → Agents → Roles
  3. 03
    Available now

    Turn intent into ready work.

    Create boards and Draft tasks. Refine the request, mark it Ready, then prepare a run manually or start project admission within your limits.

    Board → Draft task → Ready
  4. 04
    Available now

    Follow the work. Make the call.

    Run-scoped branches and worktrees keep changes organized. Launch checks authorization; passing Review waits for your local-completion or release decision.

    Prepare run → Authenticate → Inspect

02 / Keep the whole picture

Less scattered.
More in sight.

Projects, boards, agent activity, and evidence share one local workspace. Find the work that is moving—and the decision that needs you.

↗

Know what is moving.

The dashboard shows queued and active runs, task states, measured resources, and recent activity. Agent Floor adds role, runtime, model when known, and elapsed time.

◷

Keep the thread intact.

Durable events, pause, hibernate, resume, and startup reconciliation keep work inspectable. Sleep gaps and recovery decisions remain in the history.

⌘

Choose the useful tools.

Optional, scoped connectors bring RTK, XERJ, Ponytail, and MCP into the workflow. Each has detection, health, and explicit permission boundaries.

03 / Let good work leave something behind

Every project.
A little wiser.

Keep the useful discoveries after a run ends. Review knowledge candidates, preserve their evidence, and carry accepted lessons into future work.

  • 01
    Readable by you.

    Knowledge lives in Markdown, with provenance and usage records.

  • 02
    Reviewed before it travels.

    Project knowledge stays scoped until you approve global publication.

  • 03
    Connected to its evidence.

    Growth, lineage, and usage views show where knowledge came from and where it was used.
