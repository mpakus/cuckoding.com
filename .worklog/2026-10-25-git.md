## Initial policy

- Pin task bases to full commit SHAs; reopening verifies identity and preserves
  commits/files. Failure preserves worktree and reports a reason.
- Build a detached candidate; publication acquires the target through ordinary
  `worktree add`, checks expected HEAD, then fast-forwards in that owned checkout.
  Git itself refuses a target already checked out in the user source directory.
- Never update refs behind a checked-out user tree, reset/clean user files, or
  automatically stash/detach their checkout. Checks/review/queue persistence are
  future application responsibilities; a spike success is not task Done.
