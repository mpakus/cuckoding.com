## Implementation gaps found during audit
1. **Non-Codex `ExecutionRetry` (`start_timeout` / `start_checkpoint` / provider rate-limit checkpoint) rejected real `Worker` steps**:
   - `Deliveries.model_profile/4` returns `{:ok, nil}` on `:implement` when
     `implementer` is `claude`, `cursor`, or `opencode`, so `Worker.cycle` writes
     `"model_profile" => nil` into `delivery_steps.input`.
   - `ExecutionRetry.implementation_parent/2`, `ExecutionRetry.checked_parent/1`,
     and the SQLite views `execution_retry_sources`, `checkpoint_retry_sources`,
     and `provider_retry_sources` still required
     `json_type(s.input,'$.model_profile.model')='text'`, causing real non-Codex
     timeout, checkpoint, and provider rate-limit retries to fail admission
     (masked in the earlier unit test because the fixture manually populated a
     synthetic `"model_profile"` map).
2. **Mixed-runner `:resolve` routing when `implementer` is non-Codex and `analytic` is `codex`**:
   - `Deliveries.model_profile/4`, `Deliveries.pin_model!/4`, and SQLite
     triggers `delivery_catalog_model` / `delivery_model_profile` exempted
     `:resolve` whenever `implementer` was in `claude`/`cursor`/`opencode`
     (`kind in ~w(plan implement resolve)`), even though `:resolve` executes on
     `delivery.analytic`. When `implementer` was non-Codex and `analytic` was
     `codex`, `:resolve` received `profile = nil` instead of the pinned Codex
     resolver profile.
3. **SQLite retry source trigger role-pinning parity**:
   - `Retry.source/1` and `ExecutionRetry.source/1` enforce `implementer` and
     `analytic` preservation in Elixir, while `delivery_retry_source`,
     `execution_retry_source`, `checkpoint_source`, and `provider_recovery_source`
     only checked `reviewer` in SQLite.
4. **Documentation & `AGENTS.md` drift (`2026-11-11` → `2026-11-18`)**:
   - `AGENTS.md` still described Autopilot snapshots as `present New tasks` in
     the body (routing v2 snapshots eligible `new`, `failed`, `blocked`, and
     `needs_input` tasks), omitted `implementer`/`analytic` role preservation and
     empty-catalog handling on non-Codex retries, and only mentioned Cursor for
     `:lingering_processes` envelope normalization (`Claude` also shares
     `clean_envelope_exit?/1`).
   - `docs/RELEASE.md`, `docs/AUTONOMY.md`, `docs/MANAGED_DELIVERIES.md`,
     `README.md`, `CHANGELOG.md`, `tasks/plan.md`, and `tasks/todo.md` did not
     yet incorporate the verified `2026-11-14..16` `0.1.0-rc.2` 910-test
     regression, isolated runtime rebuild, clean archive + Developer ID signing
     (`e757fa1`), one-task live paid Codex Autopilot measurement (`~106s`), or
     `2026-11-15..16` notarization preflight status, and lacked a consolidated
     matrix of remaining release/platform gates.

## Decisions
- Fix `Deliveries.model_profile/4` and `Deliveries.pin_model!/4` so `implementer`
  exempts only `kind in ~w(plan implement)` while `analytic` controls `:resolve`.
- Fix `ExecutionRetry.valid_implementation_profile?/2` to accept `nil` (as well
  as a string `model_profile.model`) on parent `:implement` steps when
  `parent.implementer` is `claude`, `cursor`, or `opencode`.
- Add reversible migration
  `priv/repo/migrations/20261118120000_harden_multi_agent_retries_and_analytic_routing.exs`
  updating `execution_retry_sources`, `checkpoint_retry_sources`,
  `provider_retry_sources`, `delivery_catalog_model`, `delivery_model_profile`,
  `delivery_retry_source`, `execution_retry_source`, `checkpoint_source`, and
  `provider_recovery_source` with a history-preserving `down/0` guard.
- Synchronize `AGENTS.md`, `docs/RELEASE.md`, `docs/AUTONOMY.md`,
  `docs/MANAGED_DELIVERIES.md`, `docs/CLAUDE_REVIEW.md`, `README.md`,
  `CHANGELOG.md`, `tasks/plan.md`, and `tasks/todo.md`.
