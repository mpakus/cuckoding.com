## Implementation

`bin/dev.restart` uses system Ruby with gem loading disabled and the stdlib
already available on the supported macOS host. The entrypoint resolves the
bundle relative to its own checkout, rejects a missing/symlinked executable,
reads only PID/parent/start/executable metadata through RTK, and signals only
the exact shell after a fresh identity check. It retains the initial descendant
identities until all exit. Other Cuckoding bundles, duplicates, an orphaned
release or incomplete shutdown prevent launch; there is no force-kill fallback.

The existing `/usr/bin/open` launch is followed by bounded discovery of one
shell/release child, a loopback-only listener and healthy Cuckoding `/health`.
Both shutdown and readiness waits have a 30-second limit. Commands with no
running app start the existing bundle. Rebuilding and database upgrades remain
the existing explicit procedures. The helper neither opens/edits the database
nor reads authentication material; the menu bar still owns browser handoff.

Added `desktop/dev_restart_test.rb` to the existing developer build pipeline
and documented the new command and its behavior in `docs/DEVELOPMENT.md`.
