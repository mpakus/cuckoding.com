## Implementation and review

Version-three workflow revisions add up to four distinct custom read roles from
the displayed exact board team, between Speculator and Implementor. Configuration
binds that team revision plus Arena/Tabula/workflow revision/key. Core semantic
keys/roles/order stay fixed. Stable command replay and transactional busy/event
gates reuse the existing ledger; no migration or dependency is added.

Pure `Battles.Stages` owns fixed/selected stage order and role responsibility.
Snapshot freezes the policy and selected bindings; unused custom roles remain
planning-only. Battles/Waves use the existing claims, capacity, turn counters,
deadlines, retries and cleanup. The executor uses existing host read tools, with
both executor/domain receipt validation. Custom stages cannot write, run commands,
change criteria, bypass review or accept completion. The original Speculator plan
and ordered findings remain separate. Each finding is bounded to 512 UTF-8 bytes;
fresh preparation/review rounds clear only the current findings projection.

Advanced uses the existing guarded dialog and immutable history, with optional
Add/Up/Down/Remove and a collapsed Column names disclosure. Empty/boundary actions
are disabled. Removed roles have an explicit missing option. Team revision drift
rotates the form key once; dirty/recovered added-stage text remains visible without
Save authority. Stage cards and Inspect use the frozen public names. Custom role
repair groups navigate to the exact scoped editor; defaults are not changed.

Review traced callers, history, migration compatibility, exact binding/grant
validation, failure controls, public projection and finite prompt bounds. A
four-stage test exposed that 1,000-byte findings could make the offered maximum
unstartable even for small cards. It failed before reducing the bound to 512,
then passed without widening the 32 KiB prompt grant. Custom writing stages and
broader placement remain required work, rather than inert options in this editor.
