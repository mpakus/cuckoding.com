## Security review

- Generated files remain under `<run_dir>/agent/codex`, use mode `0600`, and reject symlinked configuration directories or files. The child receives only the run-scoped `CODEX_HOME` in addition to the host runner's scrubbed baseline environment.
- CLI arguments are constructed as argv without a shell. Models and resume identifiers are validated, and `--` terminates option parsing before provider session IDs and prompts.
- The effective grant truthfully distinguishes Codex-enforced sandbox/path/network controls from unsupported per-tool and resource-limit fields. Additional writable paths are never passed.
- Provider output is untrusted. Only a closed event vocabulary crosses into normalized events, hidden reasoning is rejected, recursive redaction precedes persistence, and command output is not copied into normalized event metadata.
- Global ChatGPT auth remained outside the run. The isolated auth failure affects only Codex sessions; no credential directory, token, unrelated home path, plugin, hook, or global configuration is copied into the child environment.
- Residual risk is the documented trusted-host boundary: Codex itself needs provider network access while its generated commands remain sandboxed and network-denied. The host command policy and Git service remain authoritative; a successful real smoke and real native resume require separately provisioned run-scoped authentication.
