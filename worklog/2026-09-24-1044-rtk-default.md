## Implementation and compatibility evidence

- Shared bundled discovery checks approved directories, executable bits, exact
  0.49.0 version and SHA-256; new run and first-stage events freeze scope policy.
  Existing runs are not changed. All role paths and resume share instructions.
- The installed Claude 2.1.142 help explicitly says bare mode skips hooks.
  Codex 0.146.0 exposes a hook-trust bypass, which is deliberately not used.
  Cursor 2026.09.15-d2fe57e has no verified permission-preserving isolated hook
  flow here. All three select Instructions only; no automatic agent-hook or
  generated hook activation is claimed. This is the approved compatibility
  fallback, not a successful native-hook acceptance result.
- Installed RTK rewrite returns exit 3 (permission still required), including
  already wrapped commands, despite its terse 0/1 help. Quoting and compounds
  are preserved without execution. The native smoke checks these actual exits.
- RTK 0.49.0 tracking ignores its enabled flag and pre-creates a :memory: file.
  A run-owned directory disables the optional SQLite tracker without persisting
  command strings; RTK_RECALL=0, RTK_TEE=0 and RTK_NO_TOML=1 disable duplicate raw
  output and repository filters. Canary smoke: exit status preserved, zero
  stderr, no persistent canary or worktree files.
- Application filtering uses the existing shell-filter adapter and RTK pipe on
  successful bounded redacted output. Original execution stays supervised and
  unchanged. Failed filters never rerun work; executable/launcher identity is
  rechecked after command completion before filtering.
- XERJ check `rtk proxy lsof -nP -iTCP:9200 -sTCP:LISTEN` found no listener.
  Direct pinned peer inspection used vibe-kanban
  `crates/executors/src/executors/claude.rs:209-256`, Apache-2.0: native hooks can
  include automatic approval callbacks, which Cuckoding must not adopt.
  RTK rewrite source `src/hooks/rewrite_cmd.rs:6-19,74-142` supplies the actual
  permission-sensitive exit protocol. No peer source was copied.
